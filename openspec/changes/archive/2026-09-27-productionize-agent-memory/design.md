## Goals / Non-Goals

**Goals:** Enable agents to resume persisted work and coordinate within a shared session without repeating completed work. Evolve session contracts to fit these outcomes while moving all runtime writes beneath the configured central AgentMemory root with repository isolation; make files authoritative and indexes disposable; make lifecycle operations recoverable and testable with injected time and fault points; demonstrate every source acceptance criterion.

**Non-Goals:** HTTP transport, cloud providers, server-generated semantic summaries, private reasoning capture, automatic import of all global sessions, system-wide installs, or making memory authoritative. Local OS users who can modify central storage are trusted: an MCP write boundary cannot prevent their direct filesystem edits. Network shares and hostile concurrent filesystem replacement are outside the supported local-filesystem deployment model.

## Decisions

### 1. Extend the current architecture

Keep one executable and existing layer folders. Add `MemoryTools`, memory-specific request/response DTOs, tier models, `IMemoryService`, `IAiLearningFileStore`, `IMemoryContentPolicy`, `IEmbeddingProvider`, `IVectorMemoryIndex`, event/recovery and archive interfaces. Use focused application services for curation, learning, retrieval, and maintenance. Extend the existing file abstraction only for shared low-level operations; contain path handling in the managed store. Retain existing stores/serializers only for capabilities that fit the new contracts; new canonical records use System.Text.Json and versioned schemas. Do not reuse freeform session Markdown as structured learning or embed it automatically. A separate executable/four new projects would duplicate the already useful composition and packaging.

### 2. Explicit repository ownership and options

Use `%USERPROFILE%/.codex/AgentMemory` as the default system storage root (resolve via the OS user-profile API, not literal environment syntax). This explicit user decision overrides the prompt's repository-local storage constraint. Layout:

```text
%USERPROFILE%/.codex/AgentMemory/
  sessions/<repository-id>/<session-id>/       # structured durable sessions
  repositories/<repository-id>/AiLearning/    # temp, short-term, long-term, events, indexes
  .vector/qdrant/                             # shared local rebuildable vector service data
  .locks/                                    # central/repository resource coordination
```

The configured central root is the only runtime write boundary. All repository and session segments are validated opaque identifiers; payloads never choose filesystem paths. Resolve repository identity from explicit configuration or a small repository identity configuration file committed intentionally; fail with actionable configuration error if no stable identity is available. Do not derive identity solely from machine path or select another repository through request parameters. Bind one repository identity per server process; all tools (including old session tools) see only that identity. Identical session IDs in different repositories cannot collide. Moving a checkout preserves identity; independent repositories receive different IDs. Sharing identity across worktrees intentionally shares memory and must be documented.

Repository source `AiLearning/README.md`, `INDEX.md`, `MCP-CONTRACT.md` and schemas describe the central runtime system, not a second runtime store. `AiLearning:Root`, if retained as a compatibility configuration name, must resolve to the current repository's managed directory under the configured central root; reject arbitrary overrides. Bind and startup-validate options. Add `SystemStorage:Root` and `Repository:Id`; process launch must specify identity.

Use source defaults: temp max age 24h (positive and <=24), cleanup 60m; short review/compaction/archive suggestions 3/7/14d; two independent confirmations; semantic result limit 10; Ollama loopback 11434 / embeddinggemma; Qdrant loopback gRPC 6334 and REST 6333. Set configurable finite quotas with initial defaults of 64 KiB record content, 1 MiB serialized request/record, JSON depth 32, 100 records per mutation batch, 100 max recall results, 1,000 temp records/session, and 10,000 active short records. Exceeding capacity produces an explicit error, never silent eviction. Use 30s embedding timeout, bounded retries/backoff, and cancellation. Environment-variable overrides follow .NET section conventions. Reject non-loopback provider endpoints for this local-only release and disable HTTP redirects/proxy routing for the embedding client.

### 3. Canonical records and indexes

Within each repository's central AiLearning directory implement the prompt's temp, short active/compacted/archive, long candidates/records/superseded/retired, events and summaries layout; add `.operations`, identity metadata and operation manifests. Sessions, lock coordination and shared vector service files use the separate central subtrees shown above. Include all record fields in prompt sections 6-8, embedding metadata in section 11, and journal/outcome fields in sections 16/20. Add record revision, operation ID, relationship type, protected flag, schema version, and separate lifecycle/index state. Unknown schema versions are reported and excluded, never silently rewritten or deleted. Paths are generated from IDs, never supplied by tool callers.

Hash a versioned normalized representation (line endings/Unicode normalization, meaningful whitespace retained) of claim content and structured data. Deduplication scope includes repository, tier, category/decision area, and temp session; a content hash alone never merges unrelated contexts or outcomes. Index manifests contain metadata and token postings for bounded lexical retrieval, revision/hash, and archive lookup. Canonical files determine truth; invalid/missing indexes rebuild safely. Recall/get verifies canonical status and hash before returning a result. Index or event failure cannot silently roll back acknowledged canonical data.

### 4. Containment, transactions, and multi-process concurrency

Resolve/canonicalize central storage root, the bound repository subtrees, and every destination; enforce path-segment boundaries with platform-correct comparison. Reject rooted identifiers, traversal, alternate separators, device names, ADS, and symlink/junction/reparse traversal, including archive manifests and migration inputs. Revalidate before committing. Use local filesystem permissions and document the trusted-writer constraint instead of claiming lexical normalization defeats hostile symlink races.

Use an OS-backed exclusive repository lock file under the central root (the same lock covers that repository's sessions and learning) with bounded cancellable acquisition across MCP processes, plus keyed async locks within a process. Initially serialize managed mutations under the repository lock to simplify correctness; readers use consistent revisions and hide incomplete operations. Never hold it during embedding network calls: read a revision snapshot, compute externally, then reacquire and compare before applying. Ordered locking and bounded lock lifetimes prevent deadlocks/unbounded dictionary growth.

For each multi-file operation, persist a sanitized intent with idempotency key, source revisions and intended destinations; stage validated files; durably flush; replace within the same filesystem; mark committed; reconcile manifests, events and vector pending work. Recovery resumes committed work and removes incomplete staging without losing originals. Intent visibility gates readers for incomplete compaction/promotion. Cancellation before commit aborts safely; after commit the response identifies the committed operation and recovery finishes ancillary work. Outcome/event IDs deduplicate replay. Mutating a record requires expected revision where callers could overwrite newer state. Duplicate idempotency keys with different payloads fail. Temp intents never duplicate raw content beyond its expiration.

### 5. Content policy and trust

Default to rejection for recognized passwords, tokens, API keys, authorization headers, private keys, and secret-bearing connection strings. Recursively scan all input strings including title, structuredData, tags, evidence, notes, legacy artifacts, migration content, and event metadata before any staging, persistence or embedding. Optional explicitly configured redaction must happen before hashing, with only redacted data proceeding. Recheck persisted content before outbound embedding and archive import. Error/log messages contain reason codes and correlation IDs, never offending values. Journal events are metadata-only and do not retain deleted content. Test common patterns/encodings and false positives; heuristics cannot prove arbitrary text contains no secret. Memory tool descriptions exclude hidden reasoning; accept concise facts/evidence/rationale, not a scratchpad field. Recall labels records as advisory and carries provenance, contradictions, and lifecycle.

Operator decision confirmed during apply: approval uses operator-managed grants bound to repository ID, record revision and action. MCP tools cannot create grants. The verifier must reject absent, mismatched or stale grants; a caller-supplied approval flag is never sufficient. Grant files are read-only inputs to the MCP process and must not be reachable through managed write operations. The local OS operator remains trusted.

### 6. Temporary and short-term lifecycle

Inject TimeProvider. Effective expiry is the earliest of persisted explicit expiry, createdAt plus configured max, and createdAt plus 24h. Preserve creation/expiry on update and restart; reject attempted extensions and invalid future creation timestamps. All read paths exclude expired temp, including direct get. A hosted sweep and opportunistic operations physically remove expired files and repair indexes. A stopped laptop cannot execute deletion: the observable hard guarantee is no access after expiry, with physical deletion at next running cleanup/startup; document this physical limitation.

Short-term defaults are review suggestions, never deletion timers. Review actions require actor, reason, evidence and expected revision. Protected/audit-required records reject removal unless repository policy provides explicit authorization; a tool argument claiming approval is insufficient. Semantic compaction is prepare/commit: prepare returns sources and revisions; the agent supplies summary, facts, questions, contradictions, evidence and source coverage. Commit validates structure/provenance/revisions and does not pretend to prove semantic truth. `memory_compact` is a convenience entry requiring the same reviewed representation. Archive originals by default; delete only under explicit configured policy. Archive stage is JSONL+gzip with ID/hash manifest, bounded decompression and full read-back verification before any source removal. Resume interrupted archive/compaction by operation ID; direct archived get uses manifest lookup and explicit includeArchived, not unbounded scans.

### 7. Evidence-based long-term learning

Separate `lifecycleState` (candidate, validated, superseded, retired, rejected) from `embeddingState` (pending_embedding, ready, failed) and `indexState` (pending, indexed, failed). This resolves the prompt's overlapping lifecycle/pending states without making a validated record become an unvalidated candidate during an outage. Expose pending_embedding in status and compatibility status projection.

Promote temp to short or short to a canonical long candidate with provenance and idempotent source marking; never silently validate. Confirmation independence requires distinct session IDs AND agent IDs AND evidence references for successful outcomes; duplicate outcome IDs are no-ops. Same actor/session repetition does not count. Persist all outcome types. Define confidence as `(1 + successes + 0.5 * partialSuccesses) / (2 + successes + partialSuccesses + failures + contradictions)`; not_applicable and stale do not add positive evidence, and stale/contradicted records are flagged/excluded from ordinary validated recall pending review. Use count changes only on explicit usage/outcome recording, not every search hit. Validation is an explicit `memory_promote` action once two independent successes exist, not a background side effect. An optional deterministic-fact policy can admit one reproducible authoritative verification; it is disabled by default. High-risk categories enumerated in prompt section 10 require explicit policy approval, never counter-only validation. Supersession/retirement preserve source/evidence/history, and canonical status blocks stale vectors immediately.

### 8. Embeddings and search

Use HttpClientFactory with Ollama POST `/api/embed`, batch input, and `truncate:false` so oversized text is reported rather than silently losing evidence. Do not hard-code dimensions: probe and validate non-empty finite vectors, consistent batch count/dimension, model identity, and version. Embed a deterministic, versioned projection of long-term claim text and selected metadata; short/temp are never automatically embedded. For oversized long-term text return a specific embedding-input error and retain canonical pending state; chunking is a future optimization, not hidden truncation.

Use official Qdrant.Client/gRPC with cosine, stable UUID point IDs derived from repository and memory ID, metadata payload described in prompt section 12, and repository/status filter indexes. Treat `repo_ai_learning_v1` as the configured collection prefix: derive a repository-specific alias by appending the stable repository ID; physical collections additionally include model fingerprint and version. Each repository can migrate models independently within the shared Qdrant service. Fingerprint includes provider, model identity/digest when available, observed dimension, and projection version. Same-dimensional different models remain incompatible. Validate stored fingerprint as well as Qdrant vector schema.

Recall orders non-expired temp, active/compacted short, then validated semantic long results; rank within each tier (lexical relevance/recent timestamp or vector score), apply a global bounded limit, and expose score kind instead of comparing lexical and cosine scores as equivalent. Empty query means recent filtered recall. Explicit candidate/retired/superseded filters allow diagnostic lookup, never implicit inclusion. Archive access is opt-in and manifest-targeted. Canonical checks enforce repository, state, content hash and revision on vector hits. When infrastructure fails, return local lexical results including eligible canonical long files with a degraded reason and no fabricated semantic scores.

Reindex is resumable/idempotent, scoped to this repository, tier, pending items, or IDs. Migration builds a versioned collection from canonical snapshots, replays subsequent revisions, verifies count/hash/sample retrieval, and atomically switches alias under a short mutation fence; retain old collection for explicit rollback. Never drop a shared collection or another repository's points. Persist active model+collection metadata as a recoverable operation so a crash after alias switch can be reconciled. Queries use the active fingerprint, not merely newly configured model. Dependency failure leaves canonical records and durable pending work; bounded retry skips permanent validation errors until corrected.

### 9. MCP and operations

Select session tools by the new workflow needs; retaining all ten old names or payloads is not a goal. Keep append_agent_memory for structured contributions and consolidate redundant reads around resume_agent_session. Retain session discovery/activation and plan/artifact capabilities only where they provide a distinct required operation. Add the source prompt's 16 section-17 tools plus `memory_rebuild_indexes`, `memory_prepare_compaction`, `memory_commit_compaction`, and `memory_update` for the required temp update behavior. Required names: status, remember, recall, get, list_review, mark_reviewed, compact, delete, archive, record_event, record_outcome, promote, supersede, retire, reindex, cleanup (16 names in section 17; the separate rebuild tool is the seventeenth required surface). Use snake_case names prefixed `memory_`, typed payloads, documented errors, cancellation injection, read-only/destructive/idempotent annotations appropriate to behavior, and output schemas for new tools. Do not let `memory_record_event` spoof state transitions: user events are observations; authoritative lifecycle events are server-generated. No arbitrary path write tool. Validate new structured contracts and publish explicit breaking-change guidance; legacy-shape tests are retained only for deliberately supported behavior.

Upgrade the MCP SDK from preview to a pinned stable compatible version after checking migration notes and running old/new client initialization/discovery/calls; research found v2.2.0 on the official release page, but compatibility is the gate, not simply the highest version. Preserve stdout protocol purity including launch scripts (run a prebuilt binary; send checks/build output elsewhere). Background jobs do only deterministic cleanup, index repair, approved archival, rotation, reconciliation and embedding retry. Health returns counts, expired/review/pending counts, dependency/model/collection/index status, last maintenance and recovery backlog without exposing content. Set finite per-job budgets and cancel on shutdown.

Compose binds `127.0.0.1:6333/6334`, pins a tested Qdrant image, and stores data in `%USERPROFILE%/.codex/AgentMemory/.vector/qdrant` via an explicitly resolved Compose bind mount; it does not install Ollama. PowerShell start/stop/check scripts are idempotent and report prerequisites, model availability, writable folders and launch command. Do not build legacy import tooling without a confirmed data-transfer need. Keep schemas and documentation in source control. Central canonical long files remain human-readable and exportable for deliberate source control or backup; they are outside the repository by user decision. Document central runtime backup and restore without silently copying learning into the repository. Do not add ignore rules that hide tracked canonical exports. No automatic Git commits. CI runs fresh restore/build, existing and new unit/filesystem/protocol tests, with a separately reported real Qdrant/Ollama integration lane and release publish smoke test.

### 10. Session continuity and shared coordination are the primary workflow

Confirmed purpose: agents resume where they left off and share work awareness within one session. Learning tiers support reuse across work; they are not the source of truth for task ownership or a dependency of resume. Durable session artifacts are intentional operational records, not temporary learning records. Temp cleanup must not erase plans, checkpoints, decisions or completed-task evidence. Do not automatically duplicate temp content into durable session artifacts or promote session content into learning.

Extend the existing session services with focused coordination/checkpoint services and canonical versioned JSON beneath `sessions/<repository-id>/<session-id>/coordination/`: context (objective, plan references, constraints, next steps), decisions, findings, tasks, handoffs, and per-agent checkpoints. Every entry has stable ID, actor, session/task links where relevant, revision, timestamps and evidence/output references. Use versioned JSON as the new coordination source of truth. Historical YAML/Markdown files remain untouched outside the active workflow; a legacy-format adapter or compatibility summary is not required. External output references are provenance, not permission to read/write arbitrary paths; report missing or unverified outputs rather than treating them as verified results.

Redesign `append_agent_memory` around a structured update batch, actor ID, operation ID and expected artifact revisions. Batches name known artifact types and record IDs, never paths, and commit all-or-none through recovery intents. Return committed artifact revisions and session change sequence. Freeform Content/AgentName/SectionTitle compatibility and memory_size_bytes are not required by the new use case; reject unsupported old payloads with clear contract guidance. Task ownership/state changes use the dedicated task operation below. Any retained artifact writer must respect reserved coordination storage and revision checks.

Add `resume_agent_session`, `checkpoint_agent_session`, and `coordinate_agent_task`. Resume returns a bounded consistent snapshot: objective/plan, constraints/decisions, completed tasks with outputs and verification status, active tasks with owners/expiry, blockers/dependencies, handoffs, next actions and changes after the requesting agent's acknowledged checkpoint. A monotonic committed session sequence and snapshot-bound pagination prevent skipped changes while others write. Return snapshot ID/revision, hasMore and continuation cursor; never silently truncate. Expired/invalid cursors request a full resync. Reading does not advance a checkpoint. Checkpoint explicitly acknowledges a fully consumed sequence and optionally records a structured handoff; it cannot acknowledge a future sequence or another agent's checkpoint. Persist checkpoints across process restart. No model-generated summary is needed for resume.

`coordinate_agent_task` accepts create, claim, renew, release, block, complete and reopen actions with task ID, actor, expected revision and operation ID. Creation uses a caller-stable work key unique within the session to deduplicate repeated delegation; semantic duplicate task detection is not guaranteed. Tasks record parent-step links, dependencies, acceptance expectations and next action. Claims use server time, persisted expiry and an increasing fencing generation, not agent name alone. Proposed configurable default lease is 15 minutes with renewal before expiry. Claiming atomically rejects an unexpired owner; renew/complete/release/block require the current unexpired token. Expiry allows an explicit new claim, never silently claims for an agent. Reclaim increments the generation so a returning stale agent cannot complete or overwrite reassigned work. Process restart preserves expiry rather than resetting it. Completed tasks cannot be reclaimed without an explicit audited reopen with reason. Block records blocker/evidence and releases the claim; dependencies prevent normal claims until prerequisites complete. Completion commits task status, output/evidence references and handoff together; validation results are reported as supplied, not inferred as passing. Lease fencing protects server mutations, not external files/tools; clients must check ownership before side effects and reconcile external work on takeover.

Use the same repository lock/recovery/content policy for all retained and new session mutations. Sessions are shared only within the bound repository and session ID; agent checkpoints do not restrict visibility of shared contributions. Local actor IDs provide provenance, not authentication. Claim expiry, conflicts, stale tokens and stale checkpoints are explicit results. New coordination tools remain usable with embedding/vector services offline.

Acceptance additions: SC1 resume after process exit reconstructs objective, plan, progress, outputs and next steps; SC2 two agents see each other's committed contributions without lost updates; SC3 concurrent claims admit one owner and expired takeover fences the prior owner; SC4 checkpoints and paginated catch-up survive restart without silently skipping changes; SC5 all SC1-SC4 work during semantic-service outages; SC6 supported contracts serve the new workflow, unsupported old payloads fail clearly, and historical files remain untouched. Run these before the semantic-learning integration milestone.

## Risks / Trade-offs

- Global mutation lock reduces throughput -> bounded laptop workload, avoid network work under lock; measure before adding finer transaction concurrency.
- Atomic rename is not a cross-file transaction or universal power-loss guarantee -> intent recovery, flush, fault injection, supported local filesystems, and explicit backups.
- Exact 24h physical removal while offline is impossible -> deny expired reads and purge immediately on restart; no redundant content in journals.
- Content detection has false positives and cannot recognize every secret -> default rejection, extensible detectors, synthetic security fixtures, and documented limits.
- Caller identity/evidence is self-reported over trusted local stdio -> independence rules prevent accidental double counting, not malicious proof fabrication; approval remains outside memory authority.
- Freeform historical sessions may contain secrets or mixed-repository content -> operator selects sessions, imports only validated safe content, reports blocked files without copying secrets.
- Model availability/quality and laptop resources vary -> explicit prerequisite checks and real paraphrase acceptance fixture; no claims from mocked vectors.

## Transition and selective reuse plan

Retain .NET hosting, DI, stderr logging, test infrastructure and useful service seams. Harden the atomic filesystem primitive rather than preserve its limitations. Retain session discovery/activation and durable plan/output concepts because resume depends on them; adapt implementations and payloads to structured state. Replace freeform append-only coordination, unrestricted overwrites, CancellationToken.None wrappers and identifier aliasing. Keep YamlDotNet only if a specifically retained capability still needs it. Existing tests are evidence, not a mandate to preserve obsolete behavior.

1. Deliver a retain/adapt/remove matrix for the existing ten tools and storage components, tracing each retained capability to a new requirement and a test. Remove redundant surface rather than implement compatibility adapters by default.
2. Initialize new structured sessions at the central root and update client configuration/documentation. Explain breaking payload and path changes. Unsupported legacy configuration fails clearly; do not silently redirect or import global sessions.
3. Leave existing user files untouched. No automatic copy, migration, format conversion or deletion is included. If a real historical-data need emerges, define a separately confirmed, bounded import scope; do not treat speculative import as a release gate.
4. Verify new resume/coordination contracts, publish cutover instructions and preserve backup/restore for new central data. Rollback to an old binary does not make new JSON sessions readable by it; document that limitation rather than maintaining dual stores.
